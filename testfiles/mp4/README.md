# ISO media / QuickTime fixtures

Verified at `2026-10-20T00:51:17+08:00`.

This corpus contains 322 media files and 2,058 parser cases, plus 46 HEIF Exif
extraction cases. The generic runner is `genutility/tests/mp4.py`:

```console
python -B -m unittest genutility.tests.mp4
python -B -OO -m unittest genutility.tests.mp4
```

Fixtures are grouped by source:

| Directory | Files | Source |
| --- | ---: | --- |
| `ffmpeg/` | 42 | Direct FFmpeg output: 37 minimal files and five earlier movies |
| `ffmpeg-derived/` | 4 | FFmpeg output with structural edits: two MJ2 movies, one HEIC image and unknown-box coverage |
| `synthetic/` | 275 | Constructed box fragments for focused parser and extraction cases |
| `regression/` | 1 | Existing QuickTime artwork input; original provenance is not recorded |

The 47 complete media files span the first two groups and the artwork
regression. Artwork has inconsistent declared metadata layouts and retains
negative parser expectations. The raw QuickTime fixtures cover video, PCM
audio and both track orders in mixed files. Completeness does not imply
conformance or reader acceptance. Synthetic fragments lack the tracks, codec
data or mandatory image properties of complete files. HEIF fragments retain
`.heic` / `.heif` names and QuickTime fragments may use `.mov`.

Manifest paths are relative to this directory and include their subdirectory.
The generic runner scans all four groups recursively.

`manifest.json` describes every input, its SHA-256, behavior and variant, and
the exact expectations for each profile, parse mode and strictness setting.
Checks sharing an expectation share an `options` list. Bytes are represented
as `{"hex": "..."}`; tuple fields become JSON arrays, preserving the distinction
from scalar values. Results check box positions, sizes, nesting, decoded
fields, unread payloads, warnings and the successfully yielded prefix before
an error. Large reference-chain inputs use an atom count instead of thousands
of repeated records. HEIF checks compare extracted TIFF bytes or the precise
exception type/message. Exif extraction alone does not validate TIFF syntax.

The original 54 tests passed before their generated inputs were migrated.
All their distinct file inputs are included, including the existing 2,481-byte
QuickTime artwork regression. Cache read counts, stream-helper bounds and
subprocess CLI behavior remain small focused tests using this corpus where
applicable. Expected results are checked-in data, never regenerated by tests.

`status` summarizes the covered cases: `accepted` means a parsed-mode check
succeeds, `rejected` means all covered parsed-mode checks reject, and
`extraction-rejected` means Exif extraction rejects. These are reader
expectations, not whole-file standards-conformance labels. For example,
protected metadata and chains longer than the implementation's 128-item
limit can be valid format constructs that this extractor cannot support.
Raw traversal can also accept a payload that parsed or strict mode rejects.

Coverage includes:

- Normal, extended and zero-size headers; UUID headers; truncated headers,
  payload overruns, parent overruns and invalid field widths.
- ISO and QuickTime metadata layouts, non-ASCII/numeric item types, registered
  key collisions, unknown atoms/versions and QuickTime user-data terminators.
- Immediate entry counts; visual/audio/hint sample-entry prefixes; media-handler
  disambiguation of `raw ` entries, truncated prefixes and track isolation; signed composition
  offsets, 32/64-bit decode times, chunk offsets and item references.
- Legacy/MIME/URI item strings, required terminators, optional URN locations,
  counted handler names, omitted names and Latin-1 fallback.
- HEIF file/idat/item-offset construction, extended idat headers, multi-extent
  items, TIFF offsets, primary selection, independent metadata scopes,
  fragment origins, local/external data references, protection, cycles,
  shared-source caching, depth boundaries and malformed extents/references.
- File/segment compatible brands, including empty and partial arrays;
  3GP AMR/AMR-WB/AMR-WB+/H263 and 3G2 QCELP/EVRC/SMV sample descriptions.
- Declared ISO/QuickTime dialects, major and compatible QuickTime brands,
  empty metadata containers, extended/late declarations, explicit overrides,
  contradictory layouts and malformed declarations in both traversal modes.
- Part 14 `mp4s`/`m4ae` entries, nested `esds`, truncated prefixes and child
  headers, MPEG-4 track references, parent scopes and future descriptor-box
  versions. Descriptor payloads are deliberately opaque; fixture acceptance
  does not assert MPEG-4 Part 1 descriptor conformance.
- 3GP asset language, UTF-8/UTF-16 text, optional album track numbers, rating,
  classification, year, location and track selection; malformed encodings,
  language fields, terminators and configuration payloads.
- MJ2 visual/PCM entries, JP2 headers, component depths, colour methods,
  signed resolution exponents, field order, profiles, prefix and subsampling;
  partial fields and opaque future colour methods.
- Atom nesting at 128/129 levels and the original 1,100-level reproduction.
- FFmpeg-generated AV1, HEVC (`hvc1`/`hev1`), AVC3, VP9, Opus, FLAC,
  AC-3 and E-AC-3 sample entries and their nested configuration boxes.
- A CENC-encrypted AVC movie with raw/parsed `schm` payload checks, and a
  complete movie with non-ASCII/binary unknown boxes followed by a known box.

To add a regression, add the smallest binary input and a manifest entry with
reviewed expectations. Always use a file-based fixture, ideally a complete
minimal file, or a fragment when necessary. `minimal-media.md` documents the
40 minimal complete files, with sizes, codec choices, regeneration and known
reader limitations; `minimal-media.json` records their measured metadata.
The test fails if any media file lacks an entry, an
entry lacks a file, or a fixture's bytes change without updating its hash.
Use explicit dialect expectations where ISO and QuickTime differ.

## External parser checks and fixture generation

pymp4 is a separate box reader; opaque boxes and swallowed nested errors
can make its acceptance misleading.
FFmpeg and FFprobe use the same libavformat parser; they are not two
independent implementations. Their different results reflect their different
operations, not a vote on validity.

The complete media fixtures were generated with FFmpeg 8.1.2. These commands
create one black 16x16 video frame or 0.128 seconds of silent mono audio:

```console
ffmpeg -f lavfi -i color=black:s=16x16:r=1 -frames:v 1 -c:v libx264 -preset veryslow -pix_fmt yuv420p -map_metadata -1 -fflags +bitexact -flags:v +bitexact testfiles/mp4/ffmpeg/media-avc.mp4
ffmpeg -f lavfi -i color=black:s=16x16:r=1 -frames:v 1 -c:v libx264 -preset veryslow -pix_fmt yuv420p -map_metadata -1 -fflags +bitexact -flags:v +bitexact -movflags +frag_keyframe+empty_moov testfiles/mp4/ffmpeg/media-fragmented-avc.mp4
ffmpeg -f lavfi -i anullsrc=r=8000:cl=mono -t 0.128 -c:a aac -map_metadata -1 -fflags +bitexact -flags:a +bitexact testfiles/mp4/ffmpeg/media-aac.mp4
```

Regeneration with another encoder/tool version may change bytes. Check parser
outputs and update expectations deliberately rather than treating new hashes
as an automatic fix.

The additional complete media started with these commands (FFmpeg 8.1.2):

```console
ffmpeg -f lavfi -i color=black:s=128x96:r=1 -frames:v 1 -c:v h263 -map_metadata -1 -fflags +bitexact -flags:v +bitexact -f 3gp testfiles/mp4/ffmpeg/media-h263.3gp
ffmpeg -f lavfi -i color=black:s=16x16:r=1 -frames:v 1 -c:v mpeg4 -map_metadata -1 -fflags +bitexact -flags:v +bitexact -f 3g2 testfiles/mp4/ffmpeg/media-mpeg4.3g2
ffmpeg -f lavfi -i color=black:s=16x16:r=1 -frames:v 1 -c:v jpeg2000 -pix_fmt rgb24 -map_metadata -1 -fflags +bitexact -flags:v +bitexact -f mov -tag:v mjp2 -brand mjp2 testtemp/ffmpeg-mj2.mov
```

The last command produces a MOV containing a complete JP2 image as its
sample. To build the MJ2 fixture, its JP2 header was moved into the `mjp2`
sample entry, leaving only the `jp2c` box as sample data, as required by
ISO/IEC 15444-3:2007 6.1.1–2. A JPEG 2000 signature was prepended, `wide`
removed, the file brands set to `mjp2`, and container lengths, `stsz` and
`stco` corrected. The JP2 component-depth field was corrected from the
encoder's 8 to 7 to match its eight-bit unsigned codestream components.
FFmpeg and FFprobe both accept the resulting media fixture. They do not
certify standards conformance.

## Shared parser and extension definitions

The runtime module is now `genutility.fileformats.isobmff`, and the atom
definitions are `genutility/fileformats/data/isobmff-atoms.tsv`. The former
`mp4` module and table were renamed without compatibility wrappers.

```python
from genutility.fileformats.isobmff import enumerate_atoms

for depth, position, code, size, fields, payload in enumerate_atoms("movie.3gp", parse_atoms=True):
    print(depth, code, fields)
```

The same iterator reads MP4, 3GP, 3G2, MJ2 (`.mj2`/`.mjp2`), HEIF/AVIF and
QuickTime. Format extensions reuse the table's grammar, parent selector,
header, version and layout columns. `profile` selects the ISO/QuickTime box
dialect, rather than a filename extension or codec. `ftyp` and `styp` expose
the major brand, minor version and every compatible brand as bytes; brand
claims are reported without treating them as proof of conformance.

Automatic selection scans top-level box headers for `ftyp` before traversal,
skipping other payloads by seeking. A major or compatible brand of `qt  `
(two trailing spaces) selects QuickTime; any other declaration selects ISO,
including unrecognized brands. Structural dialect detection runs only when
no top-level `ftyp` is available. Explicit `profile` values override the
declaration. `styp` alone does not select a whole-file dialect.

Malformed `ftyp` fields are rejected in both raw and parsed modes, preserving
previously yielded atoms. A declaration with a conflicting box layout is
parsed under the declared dialect and can fail; it does not trigger recovery
through structural dialect detection. In particular, `quicktime-artwork.mp4`
declares ISO brands but mixes ISO and QuickTime metadata layouts, so automatic
parsing now rejects it. Files without `ftyp` retain per-container detection.
Accepting a box under these rules does not establish full brand conformance.

Layouts support signed/unsigned scalars, byte fields, counted arrays and
arrays extending to the end of the box (`u8[]`, `fourcc[]`). Tail arrays must
contain whole elements and end the layout. `language:name` decodes the
packed three-letter ISO language code; `text:name` reads terminated UTF-8 or
BOM-prefixed UTF-16. A final optional scalar (`u8?:track_number`) reads a
field only when bytes remain. Existing `cstring` behavior is preserved.

Shared sample-entry prefixes expose data-reference indices, visual dimensions,
and audio version/channel/sample-size/fixed-rate fields. QuickTime version-2
audio retains its existing traversal without interpreting its extended fields.
Parent-specific definitions take precedence over wildcard dialect definitions;
JPEG 2000 `colr` is decoded only under `jp2h`, preserving other colour-box forms.
Its small decoder handles enumerated colourspaces and raw ICC profile bytes;
unknown methods retain their remaining payload. HEIF item/Exif resolution stays
in `heif.py`.

The same visual/audio prefix grammars handle `av01`, `hvc1`, `hev1`, `avc3`,
`vp09`, `Opus`, `fLaC`, `ac-3` and `ec-3` entries under `stsd`. Their codec
configuration boxes are exposed as opaque leaves; this does not decode or
validate the codec configuration. `vpcC` version 1 and `dfLa` version 0 have
FullBox headers. `tenc` versions 0/1 are also opaque; no decryption is performed.
`schm` is a leaf in both traversal modes: raw mode retains its scheme body,
while parsed mode exposes the scheme type/version and any scheme URI.

Box identifiers are unrestricted 32-bit values. Unknown non-ASCII/binary
identifiers are skipped using their validated size, just like unknown ASCII
identifiers. Numeric metadata item keys retain their existing display form.
Unknown types/versions normally warn; entries inside counted entry lists and
metadata item lists/content remain opaque without warnings.

Part 14 sample entries reuse the existing table grammar: `mp4s` has an
8-byte SampleEntry prefix and nested boxes; `m4ae` uses the audio prefix.
Both expose their data-reference index and nested `esds`. `dpnd`, `ipir`,
`mpod` and `sync` track references expose `track_IDs` through the shared
track-reference decoder. `sync` is supported in ISO and QuickTime; `dpnd`
under HEIF `iref` retains its separate item-reference representation.

`iods` is recognized under `moov`; it and `esds` recognize version 0 and
skip future versions with a warning. Their descriptor payloads remain
opaque. Part 14 whole-file rules, including compatible `mp41`/`mp42` brands
and the mandatory `dpnd` dependency of an enhancement track, are not
conformance checks performed by this iterator. Such rules must not be
applied globally to other ISOBMFF formats. The 2006 informative audio
timing guidance does not change box traversal.

Container nesting is limited to 128 levels, raising `ParseError` beyond that
implementation resource limit. Parsing covers container metadata and traversal;
it does not decode codecs, interpret ICC profiles, extract timed samples, or
validate complete format profiles. Other registered boxes, including complex
keyword/palette/channel mappings and newer codec configurations, remain opaque.
